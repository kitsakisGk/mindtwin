# Research plan

mindtwin is a research project. The software is the instrument; the **paper** is the main output.

## Working title

**mindtwin: An Open Cognitive Digital Twin Framework Integrating Knowledge Graphs, Prognostics and LLM Agents for Predictive Maintenance**

## Problem

Cognitive Digital Twins (CDTs) are described in the literature as digital twins with perception,
memory, reasoning and decision-making, built on semantic knowledge. In practice:

1. Most CDT work is **conceptual** (visions, reference architectures) or **proprietary**.
2. LLM-based twins (2025–26) are mostly demos, with little **quantitative evaluation**.
3. There is no **open, reproducible benchmark** for evaluating the cognitive functions of a twin
   (not only its predictive accuracy).

## Research questions

- **RQ1 (Architecture).** Can a modular CDT that connects a live twin, a knowledge graph,
  prognostic models and an LLM agent be built end-to-end from open components and evaluated on a
  public benchmark?
- **RQ2 (Grounding).** Does grounding an LLM agent in the twin (knowledge graph + model tools)
  improve answer accuracy and faithfulness compared with (a) an LLM given raw sensor data and
  (b) text-only RAG?
- **RQ3 (Knowledge).** Does knowledge-graph context improve fault localisation and explanation
  quality compared with purely data-driven methods?
- **RQ4 (Decisions).** Does uncertainty-aware RUL prediction lead to lower maintenance cost than
  point estimates in a simulated maintenance policy?

## Hypotheses

- **H1.** Twin-grounded agents answer factual questions about asset state with higher accuracy
  and fewer hallucinations than both baselines.
- **H2.** Knowledge-graph reasoning improves root-cause ranking (top-k accuracy).
- **H3.** Uncertainty-aware policies reduce total cost (failures + early replacements).

## Planned contributions

1. **Architecture.** A CDT reference architecture mapped to concrete, swappable components.
2. **Open implementation.** The `mindtwin` Python package (MIT), fully reproducible.
3. **Benchmark.** *TwinQA*, a question set over C-MAPSS engines with ground-truth answers
   (state, trend, RUL, cause and recommendation questions) for evaluating twin-grounded agents.
4. **Empirical study.** Experiments answering RQ1–RQ4, including ablations.

## Experiments

| ID | Question | Setup | Metrics |
|---|---|---|---|
| E1 | RQ1 | End-to-end run on FD001–FD004, streamed replay | Latency, throughput, functional coverage |
| E2 | RQ1/RQ4 | RUL models: linear, RF, GBM, LSTM/CNN, with and without uncertainty | RMSE, PHM08 score, coverage of prediction intervals |
| E3 | RQ2 | Agent variants: raw-data LLM · text RAG · twin-grounded (tools + KG) · ablations | TwinQA accuracy, faithfulness, tool-call correctness, hallucination rate |
| E4 | RQ3 | Root cause with and without KG | Top-1 / top-3 accuracy, expert-style explanation rating |
| E5 | RQ4 | Maintenance policy simulation | Total cost, failures, wasted life |

Reproducibility rules:
- Fixed seeds, recorded configs, results tables generated by scripts in `experiments/`.
- C-MAPSS evaluation protocol documented exactly (piecewise RUL cap, normalisation, test split),
  following the warnings in Ramasso & Saxena (2014).
- LLM experiments report model name, version, temperature and prompts; at least one open-weight
  model so results can be reproduced without paid APIs.
